# 技能包示例

技能包（Skill）是把一套固定流程封装起来，让 AI 每次遇到同类任务都按同一套标准执行，不用重复交代。

## 技能包长什么样

一个最小可用的技能包只有一个文件：

```text
skills/
└── wechat-article/
    ├── SKILL.md          # 技能说明，入口文件
    ├── references/       # 参考资料，按需读取
    └── scripts/          # 可选，需要跑代码时用
```

`SKILL.md` 是唯一必需的，其余按需要加。

## SKILL.md 的标准结构

```markdown
---
name: wechat-article
description: 按固定风格写公众号文章。当用户要求写公众号推文、长文、教程时使用。
---

# 公众号文章

## 什么时候用

用户提到"写推文""公众号""长文"时触发。

## 步骤

1. 确认主题、读者、篇幅，缺的主动问。
2. 按 references/style.md 里的风格要求起草。
3. 自查：术语是否过多、段落是否过长、有没有编造数据。
4. 输出 Markdown，标题层级只用二级和三级。

## 输出要求

- 结果前置，开头先说结论
- 每段不超过四行，手机阅读友好
- 不用夸张形容词，不用破折号
```

## 三个字段怎么写

| 字段 | 作用 | 写法 |
| --- | --- | --- |
| `name` | 技能标识 | 小写英文加连字符，和目录名一致 |
| `description` | 决定什么时候被调用 | 写清"做什么 + 什么时候用"，这是最关键的字段 |
| 正文步骤 | 执行的固定流程 | 编号写，每步一个动作，可验证 |

`description` 写不好，技能就永远不会被触发。把用户可能说的原话写进去，效果最好。

## 和提示词的区别

| | 提示词 | 技能包 |
| --- | --- | --- |
| 存放 | 一次对话内 | 独立文件夹，长期复用 |
| 复杂度 | 单段文本 | 可带多份参考资料和脚本 |
| 触发 | 手动粘贴 | 按 `description` 自动匹配 |

一句话：提示词是一次性的，技能包是把提示词固化成流程。

## 写完怎么验证

1. 新开一个对话，不提技能名字，只说要做什么，看能不能自动匹配上。
2. 让技能跑一遍完整任务，检查输出是否符合步骤要求。
3. 故意给一个模糊需求，看它会不会主动追问，而不是硬编。

验证不通过通常是 `description` 写窄了，或者步骤里缺少判断条件。
